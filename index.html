1. ¿Qué es una Lista Enlazada?

Concepto básico

Imagina una cadena de personas tomadas de la mano. Cada persona (nodo) sabe quién tiene a su lado derecho, pero no sabe nada de los demás. Para llegar a la persona número 5, debes empezar por la primera e ir avanzando una por una.

Una lista enlazada es exactamente eso: una estructura de datos lineal donde cada elemento (llamado nodo) contiene:

  1. Un dato (el valor que guardamos)
  2. Una referencia (un "puntero") al siguiente nodo

Array vs Lista Enlazada

  • Array: memoria contigua, acceso directo por índice arr[5], tamaño fijo.
  • Lista enlazada: memoria dispersa, acceso secuencial, tamaño dinámico.

Analogía visual

[ Dato | ->] --> [ Dato | ->] --> [ Dato | ->] --> null Nodo 1 Nodo 2 Nodo 3 (fin)

El último nodo apunta a null para indicar que la lista termina.

Tipos de listas enlazadas

TipoDescripción
Simplemente enlazadaCada nodo apunta solo al siguiente
Doblemente enlazadaCada nodo apunta al siguiente y al anterior
CircularEl último nodo apunta al primero

En esta práctica haremos una lista simplemente enlazada, que es la base de todo.

2. Ventajas y Desventajas

✅ Ventajas:
  • Tamaño dinámico (crece/decrece en tiempo de ejecución).
  • Inserción/eliminación al inicio es O(1).
  • No desperdicia memoria reservando de más.
⚠️ Desventajas:
  • No hay acceso aleatorio (debes recorrer para llegar al índice n).
  • Usa memoria extra por las referencias.
  • Peor localidad de caché que un array.

3. ¿Qué es una clase, un constructor y por qué se puede crear una clase Nodo sin "tipo de dato"?

Antes de escribir código, conviene aclarar una confusión muy común cuando se empieza con Java y las listas enlazadas. Vamos por partes.

3.1 ¿Qué es una clase en Java?

Una clase es un molde o plantilla que describe cómo serán los objetos creados a partir de ella. Define:

  • Atributos (también llamados campos o propiedades): los datos que cada objeto tendrá.
  • Métodos: las acciones que cada objeto podrá realizar.
  • Constructores: cómo se inicializa un objeto al crearlo.

Ejemplo mínimo de una clase:

public class Persona {
    String nombre;   // atributo
    int edad;        // atributo

    public Persona(String nombre, int edad) {  // constructor
        this.nombre = nombre;
        this.edad = edad;
    }
}

Aquí Persona no es un dato concreto; es el concepto "persona". Cuando escribes new Persona("Ana", 25) estás creando un objeto concreto: una persona llamada Ana, de 25 años.

3.2 ¿Qué es un constructor?

Un constructor es un método especial que se ejecuta automáticamente cuando creas un objeto con new. Sus reglas básicas son:

  • Tiene el mismo nombre que la clase.
  • No tiene tipo de retorno (ni siquiera void).
  • Sirve para dar valores iniciales a los atributos del objeto.
  • Si no escribes ningún constructor, Java crea uno vacío por defecto.
💡 Idea clave: un constructor no "devuelve" nada porque su trabajo no es calcular un valor, sino preparar un objeto recién creado. Por eso no lleva tipo de retorno. Es como el momento en que nace un bebé y se le asigna nombre: no se "devuelve" el bebé, simplemente se inicializa.

3.3 ¿Por qué se puede crear una clase Nodo "aunque no tenga tipo de dato"?

Esta es la parte que suele confundir. Vamos a desglosarla:

❌ Idea equivocada común

"Una clase necesita tener un tipo de dato, como int o String."

✅ Realidad

Una clase NO es un tipo de dato simple, pero SÍ se convierte en un tipo de dato. Es más: cuando escribes class Nodo { ... }, estás creando un nuevo tipo de dato propio llamado Nodo. Java tiene tipos primitivos (int, double, boolean, etc.) y tipos por referencia (todas las clases, incluyendo las que tú creas).

Entonces, cuando escribimos:

public class Nodo {
    int dato;
    Nodo siguiente;

    public Nodo(int dato) {
        this.dato = dato;
        this.siguiente = null;
    }
}

están pasando varias cosas a la vez:

  1. Estamos definiendo un nuevo tipo de dato llamado Nodo. A partir de ahora podemos declarar variables como Nodo x; igual que declaramos int x;.
  2. Dentro de la propia clase usamos ese tipo que estamos creando: Nodo siguiente; es una variable cuyo tipo es... ¡la misma clase que estamos definiendo! Esto se llama auto-referencia y es completamente legal en Java.
  3. El constructor public Nodo(int dato) recibe un int y lo guarda en el atributo dato. El atributo siguiente se inicializa a null porque aún no hay ningún otro nodo al cual apuntar.

🧩 ¿Por qué Nodo siguiente funciona si Nodo aún no está "terminado"?

Porque Java resuelve los tipos de la clase en dos pasadas: primero registra el nombre y sus miembros, y luego verifica que todo sea coherente. En ese momento Nodo ya existe como tipo, así que puede referirse a sí mismo. Es como una muñeca rusa: la muñeca sabe que habrá otra muñeca dentro, aunque todavía no la tenga.

Variable → [ dato: 10 | siguiente: → ] → [ dato: 20 | siguiente: null ] de tipo Nodo objeto Nodo #1 objeto Nodo #2

🔑 Resumen de por qué funciona

  • Las clases sí son tipos de dato (tipos por referencia).
  • Un constructor no lleva tipo de retorno por convención del lenguaje: no "devuelve" nada, inicializa.
  • Una clase puede contener atributos de su propio tipo. Esto es la base de las estructuras enlazadas, árboles, grafos, etc.
  • Cuando haces new Nodo(5), obtienes un objeto (instancia) que ocupa memoria, y guardas su referencia en una variable.
💡 Analogía final: piensa en la clase Nodo como el plano de una caja. El plano dice: "esta caja tiene un número y una flecha que puede apuntar a otra caja igual". Cada caja real (objeto) que fabricas con new sigue ese plano. La flecha puede apuntar a cualquier otra caja, incluso a ninguna (null).

4. Práctica paso a paso en Java

Vamos a construir una lista enlazada desde cero. No usaremos java.util.LinkedList, la construiremos nosotros para entenderla.

Estructura del proyecto

ListaEnlazada.java ← Clase principal que gestiona la lista Nodo.java ← Clase que representa cada elemento (irá anidada) Main.java ← Pruebas

PASO 1: Crear la clase Nodo

El nodo es el ladrillo fundamental. Necesita un dato y una referencia al siguiente.

public class Nodo {
    // ===== ATRIBUTOS =====
    // El valor que almacena este nodo. Usamos int para simplificar,
    // pero podría ser genérico .
    int dato;

    // Referencia al SIGUIENTE nodo de la lista.
    // Si este nodo es el último, 'siguiente' será null.
    Nodo siguiente;

    // ===== CONSTRUCTOR =====
    // Recibe el dato a guardar. 'siguiente' se inicializa en null
    // automáticamente porque es el valor por defecto de un objeto.
    public Nodo(int dato) {
        this.dato = dato;
        this.siguiente = null;   // explícito para que quede claro
    }
}

Puntos clave a entender:

  • int dato; → aquí se guarda el valor. Si quisieras una lista de Strings, sería String dato;.
  • Nodo siguiente; → ¡Esto es la magia! Un nodo contiene una referencia a otro nodo del mismo tipo. Esto es lo que forma la "cadena".
  • El constructor solo pide el dato, porque al crear un nodo nuevo siempre estará "suelto" (no apunta a nada todavía).

PASO 2: Crear la clase ListaEnlazada

Esta clase es el "administrador". Guarda la referencia al primer nodo (llamada cabeza o head) y ofrece los métodos para operar.

public class ListaEnlazada {

    // ===== ATRIBUTO PRINCIPAL =====
    // 'cabeza' apunta al PRIMER nodo de la lista.
    // Si la lista está vacía, cabeza == null.
    private Nodo cabeza;

    // ===== CONSTRUCTOR =====
    // Al crear la lista, está vacía: cabeza apunta a null.
    public ListaEnlazada() {
        this.cabeza = null;
    }

Ahora vamos a añadir los métodos uno por uno, explicando cada línea.

PASO 3: Método estaVacia()

Antes de operar, conviene saber si la lista tiene elementos.

// Devuelve true si la lista no tiene ningún nodo.
public boolean estaVacia() {
    return cabeza == null;
}

Explicación: si cabeza es null, significa que no hay ni siquiera un primer nodo, por lo tanto la lista está vacía.

PASO 4: Método insertarAlInicio(int dato)

Inserta un nodo al principio. Es la operación más eficiente de una lista enlazada: O(1).

public void insertarAlInicio(int dato) {
    // 1) Creamos el nuevo nodo con el dato recibido.
    //    En este momento: nuevo.siguiente == null, y 'cabeza'
    //    sigue apuntando al antiguo primer nodo.
    Nodo nuevo = new Nodo(dato);

    // 2) Hacemos que el nuevo nodo apunte al que era el primer nodo.
    //    Esto "engancha" el nuevo nodo delante de la lista actual.
    nuevo.siguiente = cabeza;

    // 3) Actualizamos 'cabeza' para que apunte al nuevo nodo.
    //    Ahora el nuevo nodo es oficialmente el primero.
    cabeza = nuevo;
}

Traza visual. Supón que la lista tiene 10 → 20 → null:

Antes: cabeza → [10| →] → [20| →] → null Paso 1: creamos nuevo = [5| →] (siguiente = null) Paso 2: nuevo.siguiente = cabeza ⇒ [5| →] → [10| →] → [20| →] → null Paso 3: cabeza = nuevo ⇒ cabeza → [5| →] → [10| →] → [20| →] → null
⚠️ El orden importa: si hiciéramos cabeza = nuevo antes de nuevo.siguiente = cabeza, perderíamos la referencia al resto de la lista.

PASO 5: Método insertarAlFinal(int dato)

Aquí sí debemos recorrer toda la lista para llegar al último nodo. Coste O(n).

public void insertarAlFinal(int dato) {
    // 1) Creamos el nuevo nodo.
    Nodo nuevo = new Nodo(dato);

    // 2) Caso especial: si la lista está vacía,
    //    el nuevo nodo pasa a ser la cabeza.
    if (cabeza == null) {
        cabeza = nuevo;
        return; // salimos del método
    }

    // 3) Si no está vacía, recorremos hasta el ÚLTIMO nodo.
    //    Empezamos desde la cabeza con un puntero auxiliar 'actual'.
    Nodo actual = cabeza;

    //    Mientras 'actual.siguiente' NO sea null, avanzamos.
    //    Cuando 'actual.siguiente == null', significa que 'actual'
    //    es el último nodo de la lista.
    while (actual.siguiente != null) {
        actual = actual.siguiente;
    }

    // 4) Enlazamos el último nodo con el nuevo.
    actual.siguiente = nuevo;
}

Traza visual. Lista 10 → 20 → null, insertamos 30:

Paso 1: nuevo = [30| →] (siguiente = null) Paso 2: cabeza != null, seguimos. Paso 3: actual = cabeza (nodo 10) actual.siguiente (20) != null → actual = nodo 20 actual.siguiente (null) == null → salimos del while Ahora actual es el nodo 20 (el último) Paso 4: actual.siguiente = nuevo ⇒ [20| →] → [30| →] → null Resultado final: 10 → 20 → 30 → null

PASO 6: Método imprimir()

Recorre la lista y muestra los datos. Esencial para depurar.

public void imprimir() {
    // Si está vacía, avisamos y salimos.
    if (cabeza == null) {
        System.out.println("La lista está vacía.");
        return;
    }

    // Puntero auxiliar para no perder la cabeza.
    Nodo actual = cabeza;

    // Recorremos hasta el final imprimiendo cada dato.
    while (actual != null) {
        System.out.print(actual.dato);

        // Si hay siguiente, imprimimos la flecha.
        if (actual.siguiente != null) {
            System.out.print(" → ");
        }

        actual = actual.siguiente; // avanzamos
    }
    System.out.println(); // salto de línea final
}
⚠️ Nunca muevas cabeza para recorrer. Siempre usa una variable auxiliar (actual), o perderás la referencia al inicio de la lista para siempre.

PASO 7: Método buscar(int dato)

Devuelve true si el dato existe, false si no.

public boolean buscar(int dato) {
    Nodo actual = cabeza;

    // Recorremos mientras no lleguemos al final.
    while (actual != null) {
        // Comparamos el dato del nodo actual con el buscado.
        if (actual.dato == dato) {
            return true; // encontrado
        }
        actual = actual.siguiente; // avanzamos
    }

    return false; // llegamos al final sin encontrarlo
}

PASO 8: Método eliminar(int dato)

Eliminar en una lista enlazada tiene tres casos que hay que manejar. Este es el método más delicado.

public boolean eliminar(int dato) {
    // CASO 1: lista vacía → nada que eliminar.
    if (cabeza == null) {
        return false;
    }

    // CASO 2: el dato está en la CABEZA.
    // Debemos mover 'cabeza' al siguiente nodo.
    if (cabeza.dato == dato) {
        cabeza = cabeza.siguiente; // el segundo pasa a ser primero
        return true;
    }

    // CASO 3: el dato está en medio o al final.
    // Necesitamos DOS punteros:
    //   - 'anterior': el nodo previo al que queremos borrar.
    //   - 'actual'  : el nodo que estamos examinando.
    Nodo anterior = cabeza;
    Nodo actual   = cabeza.siguiente;

    while (actual != null) {
        if (actual.dato == dato) {
            // "Saltamos" el nodo actual: anterior.siguiente
            // pasa a apuntar al siguiente de actual.
            // El nodo 'actual' queda huérfano y el GC lo libera.
            anterior.siguiente = actual.siguiente;
            return true;
        }
        // Avanzamos AMBOS punteros.
        anterior = actual;
        actual   = actual.siguiente;
    }

    return false; // no se encontró el dato
}

Traza visual. Lista 10 → 20 → 30 → null, eliminar 20:

Antes: cabeza → [10|→] → [20|→] → [30|→] → null anterior actual En el while: actual.dato (20) == 20 → ¡encontrado! anterior.siguiente = actual.siguiente ⇒ [10|→] deja de apuntar a [20] y apunta a [30] Después: cabeza → [10|→] → [30|→] → null (el nodo 20 queda sin referencias, el Garbage Collector lo elimina)

PASO 9: Método contar()

Devuelve cuántos elementos hay.

public int contar() {
    int contador = 0;
    Nodo actual = cabeza;
    while (actual != null) {
        contador++;
        actual = actual.siguiente;
    }
    return contador;
}

PASO 10: Método obtener(int indice)

Devuelve el dato en la posición indice (empezando en 0). Coste O(n).

public int obtener(int indice) {
    // Validación básica.
    if (indice < 0) {
        throw new IndexOutOfBoundsException("Índice negativo: " + indice);
    }

    Nodo actual = cabeza;
    int posicion = 0;

    while (actual != null) {
        if (posicion == indice) {
            return actual.dato;
        }
        actual = actual.siguiente;
        posicion++;
    }

    // Si salimos del while, el índice se pasó del tamaño.
    throw new IndexOutOfBoundsException("Índice fuera de rango: " + indice);
}

🧱 Código completo y unificado — ListaEnlazada.java

public class ListaEnlazada {

    // ===== CLASE INTERNA NODO =====
    // Definir Nodo como clase interna estática es una práctica común:
    // queda encapsulada y solo ListaEnlazada la usa.
    private static class Nodo {
        int dato;
        Nodo siguiente;

        Nodo(int dato) {
            this.dato = dato;
            this.siguiente = null;
        }
    }

    // ===== ATRIBUTO =====
    private Nodo cabeza;

    public ListaEnlazada() {
        this.cabeza = null;
    }

    public boolean estaVacia() {
        return cabeza == null;
    }

    public void insertarAlInicio(int dato) {
        Nodo nuevo = new Nodo(dato);
        nuevo.siguiente = cabeza;
        cabeza = nuevo;
    }

    public void insertarAlFinal(int dato) {
        Nodo nuevo = new Nodo(dato);
        if (cabeza == null) {
            cabeza = nuevo;
            return;
        }
        Nodo actual = cabeza;
        while (actual.siguiente != null) {
            actual = actual.siguiente;
        }
        actual.siguiente = nuevo;
    }

    public boolean buscar(int dato) {
        Nodo actual = cabeza;
        while (actual != null) {
            if (actual.dato == dato) return true;
            actual = actual.siguiente;
        }
        return false;
    }

    public boolean eliminar(int dato) {
        if (cabeza == null) return false;

        if (cabeza.dato == dato) {
            cabeza = cabeza.siguiente;
            return true;
        }

        Nodo anterior = cabeza;
        Nodo actual = cabeza.siguiente;

        while (actual != null) {
            if (actual.dato == dato) {
                anterior.siguiente = actual.siguiente;
                return true;
            }
            anterior = actual;
            actual = actual.siguiente;
        }
        return false;
    }

    public int contar() {
        int contador = 0;
        Nodo actual = cabeza;
        while (actual != null) {
            contador++;
            actual = actual.siguiente;
        }
        return contador;
    }

    public int obtener(int indice) {
        if (indice < 0) throw new IndexOutOfBoundsException("Índice negativo");
        Nodo actual = cabeza;
        int posicion = 0;
        while (actual != null) {
            if (posicion == indice) return actual.dato;
            actual = actual.siguiente;
            posicion++;
        }
        throw new IndexOutOfBoundsException("Índice fuera de rango: " + indice);
    }

    public void imprimir() {
        if (cabeza == null) {
            System.out.println("La lista está vacía.");
            return;
        }
        Nodo actual = cabeza;
        while (actual != null) {
            System.out.print(actual.dato);
            if (actual.siguiente != null) System.out.print(" → ");
            actual = actual.siguiente;
        }
        System.out.println();
    }
}

🧪 Pruebas — Main.java

public class Main {
    public static void main(String[] args) {
        ListaEnlazada lista = new ListaEnlazada();

        System.out.println("¿Está vacía? " + lista.estaVacia()); // true

        // Insertamos al final
        lista.insertarAlFinal(10);
        lista.insertarAlFinal(20);
        lista.insertarAlFinal(30);
        System.out.print("Tras insertar 10, 20, 30 al final: ");
        lista.imprimir(); // 10 → 20 → 30

        // Insertamos al inicio
        lista.insertarAlInicio(5);
        System.out.print("Tras insertar 5 al inicio: ");
        lista.imprimir(); // 5 → 10 → 20 → 30

        // Buscar
        System.out.println("¿Contiene 20? " + lista.buscar(20)); // true
        System.out.println("¿Contiene 99? " + lista.buscar(99)); // false

        // Contar
        System.out.println("Tamaño: " + lista.contar()); // 4

        // Obtener por índice
        System.out.println("Elemento en índice 2: " + lista.obtener(2)); // 20

        // Eliminar
        lista.eliminar(10);
        System.out.print("Tras eliminar 10: ");
        lista.imprimir(); // 5 → 20 → 30

        lista.eliminar(5); // borra la cabeza
        System.out.print("Tras eliminar la cabeza (5): ");
        lista.imprimir(); // 20 → 30

        lista.eliminar(30); // borra el último
        System.out.print("Tras eliminar el último (30): ");
        lista.imprimir(); // 20

        lista.eliminar(20); // deja la lista vacía
        System.out.print("Tras eliminar todo: ");
        lista.imprimir(); // La lista está vacía.
    }
}

¿Está vacía? true Tras insertar 10, 20, 30 al final: 10 → 20 → 30 Tras insertar 5 al inicio: 5 → 10 → 20 → 30 ¿Contiene 20? true ¿Contiene 99? false Tamaño: 4 Elemento en índice 2: 20 Tras eliminar 10: 5 → 20 → 30 Tras eliminar la cabeza (5): 20 → 30 Tras eliminar el último (30): 20 Tras eliminar todo: La lista está vacía.

5. Complejidades (Notación Big-O)

5.1 ¿Qué es la Notación Big-O?

La notación Big-O es una forma matemática de describir cómo crece el tiempo de ejecución (o el uso de memoria) de un algoritmo a medida que crece el tamaño de la entrada. No mide segundos exactos, sino el orden de magnitud del crecimiento.

Si n es el número de elementos en la lista:

  • O(1) → tiempo constante, no importa cuán grande sea n.
  • O(n) → tiempo lineal, crece proporcionalmente a n.
  • O(n²) → tiempo cuadrático, crece muy rápido (no lo usamos aquí, pero conviene conocerlo).
  • O(log n) → tiempo logarítmico, muy rápido (típico de búsqueda binaria).

5.2 ¿Qué significa exactamente O(1)?

O(1) — Tiempo constante: la operación tarda siempre lo mismo, sin importar cuántos elementos tenga la estructura. Da igual que la lista tenga 10 elementos o 10 millones: el trabajo es el mismo.

Ejemplo intuitivo: sacar la primera carta de un mazo. Tanto si el mazo tiene 10 cartas como si tiene 1000, sacar la de arriba te cuesta lo mismo: un solo movimiento.

En una lista enlazada, insertarAlInicio es O(1) porque solo hacemos 3 operaciones fijas:

  1. Crear un nodo nuevo.
  2. Hacer que su siguiente apunte a la cabeza actual.
  3. Actualizar cabeza al nuevo nodo.

Nada de eso depende del tamaño de la lista.

5.3 ¿Qué significa O(n)?

O(n) — Tiempo lineal: el tiempo crece proporcionalmente al número de elementos. Si la lista tiene el doble de elementos, tardará aproximadamente el doble.

Ejemplo intuitivo: buscar una carta concreta en un mazo desordenado. Cuantas más cartas tengas, más tiempo tardas en encontrarla (en el peor caso, las revisas todas).

En nuestra lista, insertarAlFinal, buscar, eliminar, contar y obtener son O(n) porque recorremos nodo por nodo desde la cabeza hasta encontrar lo que buscamos (o llegar al final).

5.5 Tabla de complejidades de nuestra lista enlazada

Cada fila explica qué hace la operación y por qué tiene esa complejidad:

Operación ¿Qué hace? Complejidad ¿Por qué?
Insertar al inicio Añade un nodo nuevo como primera posición de la lista. O(1) Solo cambiamos 2 referencias: la del nuevo nodo y la de cabeza. No depende del tamaño.
Insertar al final Añade un nodo nuevo como última posición de la lista. O(n) Hay que recorrer toda la lista desde la cabeza hasta el último nodo para engancharlo.
Buscar Determina si un valor existe en la lista. O(n) En el peor caso (no está o está al final) hay que revisar todos los nodos.
Eliminar (por valor) Quita el primer nodo cuyo dato coincida con el valor dado. O(n) Hay que localizar el nodo primero (recorrido) y luego reajustar referencias.
Obtener por índice Devuelve el dato en la posición i (0-based). O(n) No hay acceso directo: hay que avanzar nodo por nodo hasta la posición deseada.
Contar Devuelve cuántos elementos tiene la lista. O(n) Se recorre toda la lista incrementando un contador.
Está vacía Indica si la lista no tiene ningún nodo. O(1) Solo se comprueba si cabeza == null. Una operación fija.
💡 Truco: si guardas también una referencia al último nodo (llamada cola o tail), insertarAlFinal baja a O(1). Es un ejercicio excelente para que lo intentes.

5.6 Regla práctica para identificar la complejidad

  • ¿El trabajo que haces es siempre el mismo, sin importar el tamaño? → O(1)
  • ¿Recorres todos los elementos una vez? → O(n)
  • ¿Recorres todos los elementos y por cada uno haces otro recorrido completo? → O(n²)
  • ¿Vas dividiendo el problema a la mitad en cada paso? → O(log n)

6. Errores Comunes a Evitar

  1. Mover cabeza para recorrer → pierdes la lista entera. Siempre usa Nodo actual = cabeza;.
  2. Olvidar el caso "lista vacía" al insertar o eliminar → NullPointerException.
  3. No actualizar cabeza al eliminar el primer nodo → el nodo eliminado sigue "vivo".
  4. Mal orden en las asignaciones al insertar al inicio (nuevo.siguiente = cabeza; antes de cabeza = nuevo;).
  5. Confundir actual != null con actual.siguiente != null — son útiles en contextos distintos:
    • Recorrer todos los nodos → actual != null.
    • Detenerse en el último nodo → actual.siguiente != null.

7. Siguientes Pasos Recomendados

  1. Genéricos: cambia int por <T> para listas de cualquier tipo.
  2. Puntero a la cola para insertar al final en O(1).
  3. Lista doblemente enlazada: añade Nodo anterior; y podrás recorrer hacia atrás.
  4. Lista circular: haz que el último nodo apunte al primero.
  5. Iterador: implementa Iterator<T> para usar for-each.
  6. Invertir la lista: ejercicio clásico de entrevistas (con 3 punteros: prev, actual, sig).
